## Summary

Four follow-ups to Pagos (spec 054), now that mbe-api has shipped what they waited for:

- **Ticket (#227):**
  - A new `DocumentKind.customerPaymentTicket` goes through spec 044's document pipeline.
  - "Ver ticket" appears as a button on the payment view and an icon on list rows, only for credit payments and advances.
- **Customer name and search (#223):**
  - `CustomerPayment` carries the server's `customerName`, and `PaymentCustomerName` uses it directly. The per-customer lookup stays only as the fallback for a missing name.
  - The facility scope gets a customer-name search box.
- **Facility checks (#224):**
  - The client guards stay.
  - A 403 on the list shows a "not allowed" state with no retry.
  - The detail already maps the server's 404, so it needs only a test.
  - The walkthrough asserts the server's refusals as QA054.
- **Walkthrough (#225):**
  - A rerunnable seed script creates a credit payment applied to a back-office order.
  - The walkthrough drives the date picker dialog, fails instead of skipping when data is missing, and adds steps for the ticket and the search.

**Technical approach**: regenerate the API client (R1). After that, every change is additive to existing files, and the screen work reuses existing shared components: `CatalogSearchBar`, `buildCatalogRowActions`, `DocumentActions.preview` and `ErrorBanner`.

## Deviations found during implementation

The behaviour in the spec is unchanged; these are mechanics.

| Design said | Implemented | Why |
|---|---|---|
| "Not allowed" state is an `ErrorBanner` (C2, R7) | Centred text, keyed `payments_list_forbidden` | `ErrorBanner` prefixes a `ServerError` with the generic "server error" headline, which reads as a failure; the POS sale detail's 403 precedent is plain text too |
| Folio column `fixedWidth: 90` (spec 054) | `size: ColumnSize.S` | The row-action column is a fixed 150 px. With the 90 px Folio and the 140 px Verificado also fixed, the table's fixed widths exceeded a 400 px phone and `data_table_2` asserted. Expanded width is unaffected (layout test passes) |
| Search hint "Buscar por cliente" (C1, C5) | "Buscar cliente…" | Matches the existing reference hint, "Buscar referencia…" |
| Walkthrough steps 12 and 13 (R9) | Steps 14 and 15; the server-refusal checks are their own step, 9b | 12 was already the phone-width step |
| The regeneration might bring unrelated endpoint changes (R1) | Only `customer_payments_api.dart`, `customer_payment_response.dart` and the generated README changed | The previous regeneration was already current with every other endpoint |
